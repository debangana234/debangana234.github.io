Reservoir Sampling

Algorithms · Sampling · Genomic homology search · 14 August 2026

Reservoir sampling is useful when we want a fixed-size random sample from a stream that is too large to store. I came across this problem while thinking about large-scale genomic homology search, where the number of possible sequence pairs can easily reach tens of billions.

The Genomic Search Problem

Suppose we have two collections of fixed-length genomic sequences:

\[ A = \{a_1, a_2, \ldots, a_{n_1}\}, \qquad B = \{b_1, b_2, \ldots, b_{n_2}\}. \]

Every sequence contains \(k\) base pairs. In one application, \(n_1\) was approximately 700,000 and \(n_2\) was approximately 70,000. Comparing every sequence in \(A\) with every sequence in \(B\) therefore gives

\[ 700{,}000 \times 70{,}000 = 49{,}000{,}000{,}000 \]

possible sequence pairs.

For a pair \((a_i, b_j)\), define the homology score as the fraction of matching base positions:

\[ h(a_i,b_j) = \frac{\text{number of matching base pairs between }a_i\text{ and }b_j}{k}. \]

If two sequences of length 22 match at 18 positions, their homology score is \(18/22 \approx 0.818\). Since all sequences have the same length, the score is simple to compute. The challenge is the number of comparisons.

The Problem

The downstream analysis did not require storing all 49 billion pairs. The goal was to keep at most 10,000 sequence pairs from each homology interval:

  • \(h < 0.3\)
  • \(0.3 \le h < 0.4\)
  • \(0.4 \le h < 0.5\)
  • \(0.5 \le h < 0.6\)
  • \(0.6 \le h < 0.7\)
  • \(0.7 \le h < 0.8\)
  • \(0.8 \le h \le 0.9\)
  • \(h > 0.9\)

This means the final dataset contains at most \(8 \times 10{,}000 = 80{,}000\) pairs. A naive strategy would store all pairs in a bin and sample 10,000 at the end. That becomes wasteful if a bin contains hundreds of millions of pairs.

The question is: how can we select 10,000 uniformly random pairs from a very large stream without storing the whole stream?

The Reservoir Sampling Idea

Suppose elements arrive one at a time:

\[ x_1, x_2, x_3, \ldots, x_N. \]

We want exactly \(K\) elements, sampled uniformly without replacement, but \(N\) may be very large or unknown in advance. Reservoir sampling keeps only a fixed-size collection of \(K\) elements. This collection is the reservoir.

  1. Store the first \(K\) elements directly.
  2. When the \(i\)-th element arrives, where \(i > K\), keep it with probability \(K/i\).
  3. If it is kept, replace one existing reservoir element chosen uniformly at random.
  4. If it is not kept, discard it.
reservoir = []
count = 0

for element in stream:
    count = count + 1

    if count <= K:
        reservoir.append(element)
    else:
        j = U(1, count)  # generate a uniform random integer

        if j <= K:
            replace reservoir[j] with element

A Small Example

Let \(K = 2\), and suppose the stream is \(A, B, C\). The first two elements fill the reservoir:

\[ R = [A, B]. \]

When \(C\) arrives, it enters the reservoir with probability \(2/3\). If it enters, it replaces either \(A\) or \(B\) with probability \(1/2\). Therefore:

\[ P(C\text{ replaces }A) = \frac{2}{3}\times\frac{1}{2} = \frac{1}{3}, \] \[ P(C\text{ replaces }B) = \frac{1}{3}. \]

The final reservoir can be \(\{A,B\}\), \(\{A,C\}\), or \(\{B,C\}\). Each occurs with probability \(1/3\). That is exactly uniform sampling of two elements from three.

Why It Works

After processing \(i\) elements, reservoir sampling guarantees that every element seen so far has probability \(K/i\) of being in the reservoir.

The base case is direct. After the first \(K\) elements, all \(K\) are stored, so each has probability \(K/K = 1\).

Now assume that after processing \(i\) elements, each old element has probability \(K/i\) of being stored. When element \(x_{i+1}\) arrives, the reservoir already contains \(K\) elements. At this point, any old element in the reservoir can have one of two outcomes: it can survive this new step, or it can be replaced by the incoming element.

  • First, the incoming element \(x_{i+1}\) must be selected from the stream. This happens with probability \(K/(i+1)\).
  • If the incoming element is selected, it has to replace one of the \(K\) elements already present in the reservoir.
  • The replacement is uniform. Therefore, each old reservoir element has probability \(1/K\) of being chosen for replacement.
  • So, for a particular old element to be replaced, two events must occur together: the new element must enter the reservoir, and that specific old element must be selected for replacement.

Therefore, the probability that any particular old element is replaced is:

\[ \frac{K}{i+1} \times \frac{1}{K} = \frac{1}{i+1}. \]

Its probability of surviving is therefore \(1 - 1/(i+1) = i/(i+1)\). The probability that an old element remains in the reservoir becomes

\[ \frac{K}{i} \times \frac{i}{i+1} = \frac{K}{i+1}. \]

The new element and every old element therefore have the same probability \(K/(i+1)\) of being present. This is the central idea.

Using One Reservoir Per Homology Bin

In the homology search, every evaluated pair is assigned to one of the eight score bins. Instead of storing all pairs in a bin, we keep one reservoir per bin:

\[ R_1, R_2, \ldots, R_8. \]

Each reservoir has capacity 10,000. Each bin also needs its own counter, because the replacement probability depends on how many qualifying pairs have been seen for that bin.

For example, if a pair has \(h(a_i,b_j)=0.74\), it belongs to the \(0.7 \le h < 0.8\) bin. The counter for that bin is incremented. If the reservoir is not full, the pair is stored. If the reservoir is already full, the pair is kept with probability

\[ \frac{10{,}000}{\text{number of pairs seen so far in that bin}}. \]

If a bin eventually contains 100,000,000 qualifying pairs, every pair in that bin has probability \(10{,}000/100{,}000{,}000 = 0.0001\) of appearing in the final sample. The probability is small, but it is the same for every pair in that bin.

What Reservoir Sampling Improves

Reservoir sampling does not remove the need to compute homology scores. If every pair in \(A \times B\) is still evaluated, the search still requires \(O(n_1n_2)\) pairwise comparisons for fixed \(k\).

However, reservoir sampling improves memory. Without it, all qualifying pairs from a dense bin would need to be stored before sampling. With reservoir sampling, only \(K\) pairs are stored per bin, so memory remains fixed even when the bin contains millions or billions of pairs.

In short: reservoir sampling does not make a rare high-homology pair easier to find. It makes it possible to keep a uniform sample from a very large stream once qualifying pairs are observed.

Discovery Versus Sampling

Dense and sparse homology bins create different problems. In a dense bin, qualifying pairs are easy to find but too numerous to store. Reservoir sampling is well suited to this case.

In a sparse high-homology bin, the problem is different. We may want 10,000 pairs, but qualifying pairs may be rare. Reservoir sampling cannot solve that discovery problem.

Takeaway

Reservoir sampling is a simple way to sample uniformly from a stream while using fixed memory. Early elements enter the reservoir easily but face many future chances of replacement. Later elements enter with lower probability but have fewer future chances of being replaced. These two effects balance exactly.

For large-scale genomic homology search, this distinction matters. The exhaustive search may still be computationally expensive, but the sampled output can remain small, balanced across homology intervals, and statistically meaningful.
